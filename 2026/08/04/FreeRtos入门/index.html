FreeRtos入门

1 配置文件说明

FreeRTOS 通过 FreeRTOSConfig.h 进行 RTOS 模块配置，具体内容如下。

1.1 硬件时钟与 Tick

宏名 建议值/形式 说明
configCPU_CLOCK_HZ SystemCoreClock Tick 定时器的实际输入频率（Hz）。通常是 CPU/HCLK，但必须按硬件时钟树确认。
configSYSTICK_CLOCK_HZ 实际 SysTick 时钟 Cortex-M 专用。仅 SysTick 时钟不同于 CPU 时钟时定义；相同时通常不定义。
configTICK_RATE_HZ 100、1000 Tick 中断频率（Hz）。1000 约为 1 ms 粒度但中断开销更高；100 常用于一般控制任务。
configTICK_TYPE_WIDTH_IN_BITS TICK_TYPE_WIDTH_32_BITS TickType_t 宽度，可选 16、32、64 位；常用 32 位。旧内核使用 configUSE_16_BIT_TICKS。

1.2 调度和任务基本参数

宏名 建议值/形式 说明
configUSE_PREEMPTION 1 1 为抢占式调度，常规推荐；0 为协作式调度，任务需主动阻塞或让出 CPU。
configUSE_TIME_SLICING 1 1 时同优先级就绪任务按 Tick 轮转；0 时 Tick 到来不强制轮转。
configUSE_PORT_OPTIMISED_TASK_SELECTION 0 或 1 使用移植层提供的最高优先级任务选择优化。仅端口明确支持时启用。
configUSE_TICKLESS_IDLE 0 或 1 空闲期抑制周期 Tick 以降低功耗。须由端口支持并验证唤醒时间补偿。
configMAX_PRIORITIES 5～8 任务优先级总数；合法范围为 0 至该值减 1，0 最低。
configMINIMAL_STACK_SIZE 端口示例值起步 Idle 任务栈深度，单位 word；不代表其他任务的合适栈深度。
configMAX_TASK_NAME_LEN 16 任务名最大字符数，含结尾 \0；会影响每个 TCB 的 RAM。
configIDLE_SHOULD_YIELD 1 Idle 任务是否让出给同为优先级 0 的应用任务；通常保持 1。
configTASK_NOTIFICATION_ARRAY_ENTRIES 1 每任务的通知槽位数；增大可用索引通知 API，但增加 TCB RAM。
configNUM_THREAD_LOCAL_STORAGE_POINTERS 0 每个任务的线程本地存储指针数量；不使用则为 0。
configSTACK_DEPTH_TYPE size_t 任务栈深度参数和栈余量返回值的类型。
configENABLE_BACKWARD_COMPATIBILITY 0 是否映射旧版 API 名称/类型；新工程建议关闭。
configUSE_MINI_LIST_ITEM 端口默认值 可节省部分 RAM，但可能影响依赖严格别名优化的编译器。

1.3 内存分配与对象 RAM

宏名 建议值/形式 说明
configSUPPORT_STATIC_ALLOCATION 1 编入 xTaskCreateStatic() 等静态创建 API；纯静态系统建议开启。
configSUPPORT_DYNAMIC_ALLOCATION 0 或 1 编入 xTaskCreate() 等动态创建 API；启用时需编入合适的 heap_x.c。
configTOTAL_HEAP_SIZE 按峰值核算 FreeRTOS 堆大小（字节）。适用于 heap_1.c、heap_2.c、heap_4.c，不适用于 heap_3.c。
configAPPLICATION_ALLOCATED_HEAP 0 或 1 1 时应用定义 ucHeap[]，可把堆置入指定 RAM 段。
configSTACK_ALLOCATION_FROM_SEPARATE_HEAP 0 或 1 1 时任务栈使用独立堆，须实现 pvPortMallocStack() 和 vPortFreeStack()。
configHEAP_CLEAR_MEMORY_ON_FREE 0 或 1 释放 FreeRTOS 堆块时是否清零；有信息清理价值，但增加释放时间。
configENABLE_HEAP_PROTECTOR 0 或 1 为 heap_4.c/heap_5.c 启用内部指针保护，帮助发现堆损坏。
configUSE_NEWLIB_REENTRANT 0 为每任务配置 newlib 重入结构；RAM 开销较大，仍需处理 newlib 的 malloc 锁。
configMESSAGE_BUFFER_LENGTH_TYPE size_t 消息缓冲区中每条消息长度字段类型；消息很小时可改小以节省空间。

静态分配开启后，通常还需实现 vApplicationGetIdleTaskMemory()；若启用软件定时器，通常还需实现 vApplicationGetTimerTaskMemory()。

1.4 软件定时器、事件组和流缓冲区

宏名 建议值/形式 说明
configUSE_TIMERS 0 或 1 启用软件定时器和 Timer Service 任务；启用时工程必须编译 timers.c。
configTIMER_TASK_PRIORITY 较高优先级 定时器服务任务优先级。回调在该任务内运行，不要在回调中长时间阻塞。
configTIMER_TASK_STACK_DEPTH 按回调调用链核算 定时器服务任务栈深度，单位 word。
configTIMER_QUEUE_LENGTH 按峰值核算 Timer Service 命令队列长度；频繁启停定时器或 ISR 操作时需增加。
configUSE_DAEMON_TASK_STARTUP_HOOK 0 或 1 启用后实现 vApplicationDaemonTaskStartupHook()，在调度器启动后初始化。
configUSE_EVENT_GROUPS 0 或 1 启用事件组；启用时工程必须编译 event_groups.c。
configUSE_STREAM_BUFFERS 0 或 1 启用流缓冲区和消息缓冲区；启用时工程必须编译 stream_buffer.c。
configUSE_SB_COMPLETED_CALLBACK 0 为每个流/消息缓冲区指定完成回调的高级功能；MPU 端口可能不支持。

1.5 同步、通知与可选功能

宏名 建议值/形式 说明
configUSE_TASK_NOTIFICATIONS 1 启用任务通知。它通常比二值信号量更轻量。
configUSE_MUTEXES 1 启用互斥锁和优先级继承。
configUSE_RECURSIVE_MUTEXES 0 或 1 启用递归互斥锁；依赖 configUSE_MUTEXES=1。
configUSE_COUNTING_SEMAPHORES 0 或 1 启用计数信号量。
configUSE_QUEUE_SETS 0 启用队列集；只有一个任务必须等待多个队列/信号量时才考虑，RAM 开销较高。
configUSE_APPLICATION_TASK_TAG 0 为任务附加应用 Tag；会增加 TCB 存储。
configUSE_POSIX_ERRNO 0 启用每任务 FreeRTOS_errno；仅 POSIX/相关适配层需要时开启。
configUSE_CO_ROUTINES 0 启用协程并要求编译 croutine.c；新设计通常优先使用任务通知或状态机。
configMAX_CO_ROUTINE_PRIORITIES 1 协程优先级总数；仅启用协程时有效。

1.6 Hook、断言、栈与运行时诊断

宏名 建议值/形式 说明
configUSE_IDLE_HOOK 0 或 1 启用后必须实现 vApplicationIdleHook()；不得阻塞。
configUSE_TICK_HOOK 0 或 1 启用后必须实现 vApplicationTickHook()；它在 Tick ISR 中运行，必须极短。
configUSE_MALLOC_FAILED_HOOK 调试期 1 启用后实现 vApplicationMallocFailedHook()；动态分配工程调试阶段建议开启。
configCHECK_FOR_STACK_OVERFLOW 调试期 2 0 关闭；1 检查栈指针越界；2 额外检查边界填充值。非 0 时实现栈溢出 Hook。
configGENERATE_RUN_TIME_STATS 0 或 1 启用任务累计运行时间统计；需要高分辨率单调计数器及端口对应的统计宏。
configUSE_TRACE_FACILITY 调试期 1 为跟踪/可视化工具增加对象字段；增加对象 RAM。
configUSE_STATS_FORMATTING_FUNCTIONS 0 编入旧的格式化统计 API；会引入字符串格式化代码。
configSTATS_BUFFER_MAX_LENGTH 匹配实际缓冲区 旧格式化统计 API 假定的最大输出缓冲区长度。
configQUEUE_REGISTRY_SIZE 0 内核感知调试器可登记的队列/信号量数量；不使用时为 0。
configASSERT(x) 应用自定义 断言失败动作。调试期建议记录文件/行号后停机或复位。
configCHECK_HANDLER_INSTALLATION 1 ARMv7-M/ARMv8-M 端口检查 SVC/PendSV 是否按直接路由方式正确安装；自定义间接路由时一般为 0。

configCHECK_FOR_STACK_OVERFLOW=2 不能代替栈余量检查、静态分析和真实负载测试。开发期间建议同时开启 INCLUDE_uxTaskGetStackHighWaterMark。

1.7 Cortex-M 中断优先级

宏名 建议值/形式 说明
configPRIO_BITS __NVIC_PRIO_BITS NVIC 实现的优先级位数。CMSIS 未提供时按芯片数据手册填写。
configLIBRARY_LOWEST_INTERRUPT_PRIORITY 芯片允许的最低逻辑优先级 常用于推导内核中断优先级。
configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY 按系统中断设计填写 可调用 FromISR API 的最高逻辑优先级；数值更小的更高优先级 ISR 不得调用 FreeRTOS API。
configKERNEL_INTERRUPT_PRIORITY 左移后的寄存器值 Tick 和 PendSV 的优先级，通常为最低优先级。
configMAX_SYSCALL_INTERRUPT_PRIORITY 左移后的寄存器值 调用 FreeRTOS ISR API 的阈值。不得设为 0。
configMAX_API_CALL_INTERRUPT_PRIORITY 端口别名 某些端口采用此名代替上一项；遵循当前 port 的要求，通常无需两者都定义。

典型写法中的移位量是 (8 - configPRIO_BITS)，但 configPRIO_BITS、库优先级值和最终寄存器编码都必须与芯片匹配。

1.8 MPU、TrustZone 与 ARMv8-M 专用项

宏名 建议值/形式 说明
configINCLUDE_APPLICATION_DEFINED_PRIVILEGED_FUNCTIONS 0 Cortex-M MPU 端口中允许应用定义特权函数；完成安全架构设计后才考虑启用。
configTOTAL_MPU_REGIONS 芯片实际值 实际 MPU 区域数量，常见 8 或 16，必须查芯片数据手册。
configTEX_S_C_B_FLASH 端口默认或存储器设计值 Flash MPU 区域的 TEX、S、C、B 属性。
configTEX_S_C_B_SRAM 端口默认或存储器设计值 SRAM MPU 区域的 TEX、S、C、B 属性。
configENFORCE_SYSTEM_CALLS_FROM_KERNEL_ONLY 按安全设计 MPU 端口中应用特权提升和系统调用策略。
configALLOW_UNPRIVILEGED_CRITICAL_SECTIONS 安全系统通常 0 是否允许非特权任务进入临界区。
configUSE_MPU_WRAPPERS_V1 新工程 0 0 使用 MPU wrapper v2；仅为兼容旧工程设为 1。
configPROTECTED_KERNEL_OBJECT_POOL_SIZE 最大对象并存数 MPU wrapper v2 的受保护内核对象池容量。
configSYSTEM_CALL_STACK_SIZE 按任务系统调用链核算 MPU wrapper v2 的每任务系统调用栈深度，单位 word。
configENABLE_ACCESS_CONTROL_LIST 0 或 1 MPU wrapper v2 的 ACL；启用后非特权任务需显式获授对象访问权。
secureconfigMAX_SECURE_CONTEXTS 最大安全上下文数 ARMv8-M 安全侧最多可由任务使用的安全上下文数。
configKERNEL_PROVIDED_STATIC_MEMORY 端口相关 ARMv8-M 端口中由内核提供 Idle/Timer 静态内存实现的开关。
configENABLE_TRUSTZONE 硬件/架构相关 ARMv8-M 非安全侧调用安全侧服务时启用。
configRUN_FREERTOS_SECURE_ONLY 架构相关 整个应用仅在安全侧运行时使用。
configENABLE_MPU 硬件/架构相关 ARMv8-M 端口是否启用 MPU。
configENABLE_FPU 硬件/编译选项相关 ARMv8-M 端口是否启用 FPU。
configENABLE_MVE 硬件/编译选项相关 仅支持 MVE 的 Cortex-M 内核可启用。

1.9 SMP 多核专用项

宏名 建议值/形式 说明
configNUMBER_OF_CORES 实际核心数 参与 SMP 调度的核心数。单核项目不应设为大于 1。
configRUN_MULTIPLE_PRIORITIES 通常 0 0 尽量保持传统优先级语义；1 允许不同优先级任务跨核同时运行。
configUSE_CORE_AFFINITY 0 或 1 是否启用任务核心亲和性 API。
configTASK_DEFAULT_CORE_AFFINITY tskNO_AFFINITY 未指定亲和性任务的默认核心掩码。
configUSE_TASK_PREEMPTION_DISABLE 0 允许逐任务选择抢占/协作模式；仅 SMP。
configUSE_PASSIVE_IDLE_HOOK 0 被动 Idle Hook；不得阻塞。
configTIMER_SERVICE_TASK_CORE_AFFINITY tskNO_AFFINITY Timer Service 任务的核心亲和掩码。
configIDLE_AFFINITY 0 是否把每个 Idle 任务固定在对应核心。

1.10 INCLUDE API 裁剪项

宏名 控制的 API 与用途
INCLUDE_vTaskPrioritySet vTaskPrioritySet()：运行时修改任务优先级。
INCLUDE_uxTaskPriorityGet uxTaskPriorityGet()：读取任务优先级。
INCLUDE_vTaskDelete vTaskDelete()：删除任务；动态任务资源通常由 Idle 任务回收。
INCLUDE_vTaskSuspend vTaskSuspend() 和 vTaskResume()。
INCLUDE_xTaskDelayUntil xTaskDelayUntil()：固定周期任务的常用延时 API；旧内核可能使用 INCLUDE_vTaskDelayUntil。
INCLUDE_vTaskDelay vTaskDelay()：相对延时。
INCLUDE_xTaskGetSchedulerState xTaskGetSchedulerState()。
INCLUDE_xTaskGetCurrentTaskHandle xTaskGetCurrentTaskHandle()。
INCLUDE_uxTaskGetStackHighWaterMark 栈历史最小余量查询；开发和栈调优阶段建议开启。
INCLUDE_xTaskGetIdleTaskHandle xTaskGetIdleTaskHandle()。
INCLUDE_eTaskGetState eTaskGetState()。
INCLUDE_xTimerPendFunctionCall xTimerPendFunctionCall()：将函数提交至 Timer Service 任务执行。
INCLUDE_xTaskAbortDelay xTaskAbortDelay()：取消任务阻塞。
INCLUDE_xTaskGetHandle xTaskGetHandle()：按名称查找任务句柄。
INCLUDE_xTaskResumeFromISR xTaskResumeFromISR()；事件同步通常优先考虑任务通知或信号量。

2 堆栈

堆（stack）：由编译器自动分配和释放，比如存放函数参数、局部变量等 栈（heap）：一般手动分配和释放，类似数据结构中的链表

示例如下，参考知乎

  1. 全局变量和常量属于静态区(Static)，由编译器分配，生命周期贯穿整个程序
  2. 函数的参数、局部变量值属于栈(Stack)，由编译器自动分配和释放
  3. 手动用 malloc 函数请求分配的内存空间属于堆(heap)，如果动态分配的内存用完后没有释放内存，会导致内存泄露

2.1 任务如何分配空间

当调用 FreeRTOS 的创建任务函数 xTaskCreate() 时，FreeRTOS 会在堆中开辟一块空间，用于存放任务的控制信息 TCB 块和栈区 Stack用于储存任务相关的变量

2.1.1 TCB 块

TCB 定义如下

TCB 块的大小取决于 FreeRTOSConfig.h 头文件中的配置

  • 最小 TCB 大小为 96 字节
  • 如果configUSE_TASK_NOTIFICATIONS是 1 的话再增加 8 个字节
  • 如果configUSE_TRACE_FACILITY是 1 的话再增加 8 个字节
  • 如果configUSE_MUTEXES是 1 的话再增加 8 个字节

2.2 内存分配方案

2.2.1 heap-1

适用于小型嵌入式系统。此时系统只能在调度器启动之前创建任务和其他内核对象。如果系统运行后不需要删除任务或内核对象以及不需要动态分配内存的系统可采用这个方案

2.2.2 heap-2

保持 FreeRTOS 的向下兼容

2.2.3 heap-3

使用标准库中的 malloc、free 函数，所以堆的大小由链接器配置决定，与 configTOTAL_HEAP_SIZE 无关

heap-3 调用 malloc、free 时会临时挂起 FreeRTOS 调度器以保证线程安全

2.2.4 heap-4

此方案同第一个和第二个方案一样，由一个数组表示堆，并把数组分割成小的内存块。堆的大小由FreeRTOSConfig.h文件中configTOTAL_HEAP_SIZE定义。

Heap_4采用的first fit算法可以把相邻的空闲的内存块合并成更大的内存块，减少了内存碎片化的风险。所以这个方案适用于通用的应用（系统会添加和删除不同大小的任务），cubemx 生成的 FreeRTOS 默认采用此方案

2.2.5 heap-5

类似heap-4, 不同于 Heap_4 只用一个连续的数组表示堆，Heap_5 可以用不同的数组空间对内存进行分配

2.3 相关函数

返回当前堆中的空闲空间大小，单位为字节

返回系统运行过程中堆空间的最小空闲空间，只能在 heap-4 或 5 下使用

如果配置文件中 configUSE_MALLOC_FAILED_HOOK 设置为 1 的话，当堆分配内存失败时会调用此函数。可以在此函数中进行错误处理
